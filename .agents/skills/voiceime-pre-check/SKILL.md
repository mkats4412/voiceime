# VoiceIME コードチェック直前の安全確認スキル (Pre-Check Protocol)

VoiceIME のソースコードを変更・リファクタリング・最適化・チェックする前に、**必ずこのスキルを読んで以下の禁止事項・保護領域を遵守してください**。

---

## 💾 【事前必須ステップ】チェック前の状態を必ず git stash で退避・保存

コードチェック・リファクタリング・修正に入る直前には、作業ツリーに未コミットの変更がある場合、必ず `git stash` を実行して「チェック前の状態」を確実に保持・バックアップしてください。

```bash
# 未コミットの変更がある場合は、タイムスタンプ付きで安全にスタッシュ退避
if [ -n "$(git status --porcelain)" ]; then
    git stash push -u -m "pre-check-backup-$(date +%Y%m%d_%H%M%S)"
    echo "✅ チェック前の作業ツリー状態を stash に退避・保存しました"
fi
```
* これにより、チェックやリファクタリング作業中に意図しないコード喪失やデグレが発生した場合でも、いつでもチェック直前の状態（`git stash pop` / `git stash list`）へ即座に復元・比較できるようにします。

## 🛑 【絶対禁止】コードチェックで壊してはいけない 4 大保護領域

### 1. CoreAudio / AVAudioEngine（マイク入力とストリーミング）
* **禁止コード**: `engine.inputNode.auAudioUnit.setDeviceID(...)`
  * **理由**: `AVAudioEngine` の `inputNode` に対して `setDeviceID` を直接呼ぶと、AUHAL の入力チェーン初期化状態が破壊され、`engine.start()` 時に **`kAudioUnitErr_FormatNotSupported` (エラー `-10868`)** で 100% クラッシュ・起動失敗します。
  * **ルール**: 入力デバイスは常にシステムのデフォルト入力として `AVAudioEngine` に自然に開かせてください。
* **マイクタップのフォーマット**:
  * `inputNode.installTap(onBus: 0, bufferSize: 1024, format: recordingFormat)`
  * `let recordingFormat = inputNode.outputFormat(forBus: 0)` をそのまま渡してください。`format: nil` に変更してはいけません。
* **SFSpeechRecognizer の過剰ガード禁止**:
  * `SFSpeechRecognizer.authorizationStatus() == .authorized` だけでタスク生成をスキップしてはいけません（`.notDetermined` の初動リクエストが死にます）。

### 2. Push-to-Talk リアルタイム表示（Whisperストリーミング表示の厳守）
* **必須挙動**:
  * ユーザーがキー（例: `Ctrl+Space`）を押しながら話している最中（手を離す前）に、**Whisper（StreamingChunkPipelineService）から返ってきた認識結果** がリアルタイムでフローティング画面に随時出力され、**「目視確認できる状態」** でなければなりません。
* **厳格なルール（macOS STT の表示禁止）**:
  * macOS 標準の STT（Apple Speech / SFSpeechRecognizer）の不完全な出力を画面に出してはいけません。
  * `LiveSpeechService` の `startLiveRecognition` コールバックは必ず `{ _ in }` のままにし、Apple STT で `FloatingPreviewController.shared.updateLiveText` を上書きしないこと。
  * 画面に表示するのは、`StreamingChunkPipelineService` から `updatePipelineText` で届く本物の Whisper 結果のみです。
  * 「キーを離した瞬間に一瞬文字が出てすぐペーストされて消える」状態はデグレ（バグ）です。話している最中に Whisper の途中結果（息継ぎ速報）が随時出力されている必要があります。
  * `FloatingPreviewController` のテキスト更新を排他ロック等でブロックしないこと。

### 3. 音声入力しきい値のユーザー設定直結と無音時無駄送信の防止
* **しきい値のハードコード厳禁**:
  * `StreamingChunkPipelineService` のしきい値計算で、`-4.0dB` や `-34.0dB`、`-42.0dB` などの固定オフセットを勝手に差し挟まないこと。
  * 必ずユーザーが設定画面で調整した `settings.audioThresholdDB` を 100% ダイレクトに連動させてください（`pow(10.0, speechThresholdDB / 20.0)`）。
  * ハードコードで数値を勝手に引き下げると、環境ノイズフロアに埋もれてアプリが「ずっと話している（`silent: 0.00s`）」と誤認し、重大なデグレを引き起こします。
* **有声発話フレーム時間（`newSpeechDuration`）によるトリガー厳守**:
  * トリガー判定（`shouldTrigger`）を、単なるサンプルの経過時間（`newAudioDuration`）で行ってはいけません。
  * 必ず音量しきい値を超えた **有声発話時間（`speechFramesSinceLastTrigger` / `newSpeechDuration`）** を追跡し、前回の送信以降に「新たな発話（有声）」が加わった時だけトリガーすること。話していない沈黙中に同じ音声を Whisper API に送り続ける無駄送信ループを絶対に起こさないこと。

### 4. macOS キーチェーン認証と起動時ガイダンス
* **初回起動案内ウィンドウの維持**:
  * アプリ更新・再コンパイル後の初回起動時には、最前面に **「VoiceIME: macOS キーチェーン認証のご案内」** ダイアログを表示し、ユーザーに「了解して認証へ進む」を押させて起動直後に `keychain.warmUp()` で事前認証を完了させてください。
  * これを削除すると、音声入力（CTRL+Space）の瞬間に macOS のシステムパスワードダイアログが突然飛び出してきて音声入力を遮断してしまいます。
* **MCP モード (`--mcp`) の完全サイレント化**:
  * `voiceime --mcp` で起動される MCP サーバー時は、GUI（`AppState`）を初期化せず headless 実行し、ダイアログを絶対に表示させないこと。

## 🔍 コード精査における 10 大チェック観点

コードチェックを指示された際は、上記の 4 大保護領域を厳守した上で、以下の観点に沿ってコードを精査してください：

1. **メモリ管理・ポインタ安全性**
   - メモリリーク（解放漏れ、循環参照、`[weak self]` / ライフサイクル不備）
   - ヌル参照（Null / Nil Pointer Dereference）、強制アンラップ（`!`）によるクラッシュ
   - 不正なポインタ操作、無効な領域へのアクセス
2. **並行処理・スレッドセーフティ**
   - データ競合（Data Race）、排他制御の不足
   - デッドロックの危険性、メインスレッド（UI）のブロック
3. **境界値・配列安全性**
   - 範囲外アクセス（Index Out of Range）、空コレクションの扱い
   - ループ境界条件、数値のオーバーフローや型キャスト時のリスク
4. **エラーハンドリング・後始末**
   - エラーの握りつぶし、不十分な例外処理
   - 早期リターン時のクローズ漏れ（`defer` 等の適切な利用）
5. **リソースライフサイクル**
   - ファイルハンドル、接続、タイマー、通知オブザーバーの破棄漏れ
   - バックグラウンドタスクの生存期間管理
6. **セキュリティ**
   - ハードコードされた秘密情報（APIキー・トークン・パスワード・証明書）が無いか
   - インジェクション（SQL・シェル・eval/exec・XSS）、パストラバーサル、安全でないデシリアライズが無いか
7. **ログ・デバッグ出力の残留**
   - `print`/`NSLog` 等に個人情報や音声認識結果が出ていないか
   - デバッグ用コード、コメントアウト、TODOの残留が無いか
8. **ロジック正誤**
   - 仕様・意図どおりに動くか（クラッシュしない≠正しい）
   - 条件分岐・off-by-one・誤った前提の有無
   - 音声ストリーミングトリガーにおいて、沈黙（無音）中の無駄送信ループが発生しないロジックになっているか（有声発話時間の追跡確認）
9. **環境依存・設定無視の排除**
   - 絶対パス、マシン固有の設定、ローカル専用ホストの直書きが無いか
   - ユーザー設定値（`audioThresholdDB` など）を無視・加工する勝手なハードコード（`-4dB` 等）が存在しないか
   - 他人の環境でもビルド・実行できるか（前提の明記、設定の外部化）
10. **私物の混入チェック**
    - 氏名・メール・端末名・私用URL・社内情報・私的メモの紛れ込みが無いか
    - 自分専用のテストデータが残っていないか

## 📤 レポート出力フォーマット

コードチェック結果を報告する際は、必ず以下のフォーマットに従ってください：

1. **発見された問題点（該当箇所・原因・発生しうるリスク）**
2. **問題を解消した修正内容（差分形式または修正箇所のみ＋理由。大規模な書き換えはしない）**
3. **主な修正ポイントと改善理由の解説**

## 🧪 修正完了後の必須検証コマンド

コード変更後は、必ず以下の手順を実行してデグレがないことを確認してください：

```bash
# 1. ユニットテストの実行
./scripts/run_tests.sh

# 2. アプリのビルド & インストール
./scripts/build_app.sh --install

# 3. アプリの再起動
killall VoiceIME && sleep 1 && open /Applications/VoiceIME.app

# 4. 実機での確認
# Ctrl+Space を押しながら話し、手を離す前にフローティング画面に文字が出ることを目視確認する。
# ~/.voiceime/pipeline.log を確認し、エラー -10868 が出ていないことを確認する。
```
